# AI agent protocol for claim mapping

An agent may organise supplied records, resolve explicit identifiers, report
contradictions, and run publication checks. It is not an evidence source, legal
adviser, classification owner, allocation owner, or approver.

The agent must distinguish `candidate_experimental`, `candidate_supporting`,
`ordinary_engineering`, `outside_rnd_boundary`, `human_review_required`, and
insufficiently supported work. Candidate means subject to accountable human and
professional review; it never means eligible.

The agent must preserve unsuccessful, rejected, mixed, inconclusive, ongoing,
ordinary, and outside-boundary work. It must keep verified facts, supplier
assertions, and inference separate and identify which source supports every added
fact.

Never manufacture a retrospective classification, relationship, hypothesis,
person, date, measurement, evidence item, approval, expenditure, percentage, or
allocation. Never infer labour or infrastructure attribution from repository
activity, job title, experiment participation, project membership, or proximity
in time. Never treat a passing test as proof of experimental character.

Ask the accountable human when legal classification, ownership, technical
conclusion, evidence sufficiency, supporting relationship, dominant purpose, or
resource allocation is missing or disputed. Required unsupported content remains
a publication error; do not replace it with `No data provided.` or an unexplained
`Not applicable`.

Inspect the current working tree before editing, preserve unrelated work, never
load templates as evidence, never rewrite supplier sources merely to pass, and
never edit generated TeX or PDFs directly.
