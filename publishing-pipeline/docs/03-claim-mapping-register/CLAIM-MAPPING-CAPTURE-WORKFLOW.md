# Claim mapping capture lifecycle

1. Create the project and uncertainty only from supported supplier records.
2. Screen each activity and preserve its supplier-authored classification and
   accountable classification owner.
3. Create candidate experimental links when the activity actually names the
   uncertainty and experiment run.
4. Create a supporting link when the supporting purpose is recorded. Name the
   supported candidate activity or run; do not derive it from context.
5. Capture experiment execution, observations, and evidence through the existing
   document-02 sources without copying them into a mapping source.
6. Record people on activities and runs only when participation was supplied.
7. Add timesheet and infrastructure activity attribution when the underlying
   record identifies it. Otherwise leave publication blocked or mark the entire
   conditional category not applicable with an accountable reason.
8. Record ordinary and outside-boundary work without deleting or relabelling it.
9. Open a stable review record for unresolved legal, technical, evidentiary,
   ownership, classification, or allocation decisions. Update its status; do not
   rewrite its history. A replacement review supersedes the old ID.
10. Reconcile reciprocal references and publish. Failed validation or compilation
    leaves the previous generated files and PDFs unchanged.

Review mappings when an activity changes boundary, a run is created or closed,
new evidence is registered, effort or cost attribution is supplied, a decision is
resolved, or the annual record is closed. Preserve prior IDs and outcomes.
